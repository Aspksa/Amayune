# Подготовка подписанных обновлений Amayune

Сервер предоставляет `GET /api/update/check` и `POST /api/update/stage`. Оба маршрута требуют токен текущей локальной сессии (`x-amayune-token`).

Для подготовки необходимо настроить `AMAYUNE_UPDATE_PUBLIC_KEY` с доверенным Ed25519 PEM-ключом, заранее полученным из независимого доверенного источника. Запрос `POST /api/update/stage` принимает JSON `{ "sha": "<40-символьный SHA коммита>", "manifest": { "signatureAlgorithm": "ed25519", "files": [{ "path": "web/app.js", "sha256": "<SHA-256>" }], "signature": "<base64 Ed25519>" } }`. Подпись проверяется над UTF-8 строкой `JSON.stringify({files:manifest.files})`.

Перед загрузкой сервер повторно сверяет SHA с текущей веткой main и требует успешный CI. Файлы скачиваются из зафиксированного коммита с ограничениями размера, проверяются по SHA-256 и помещаются в `.runtime/updates/staged`; манифест сохраняется отдельно. Если подготовленная версия уже существует, новая не заменяет её автоматически.

**Важно:** это подготовка, а не установка. Установку, перезапуск и откат необходимо реализовать отдельным этапом, включая проверку здоровья приложения и сохранение пользовательских данных. Не копируйте приватный ключ подписи на пользовательские компьютеры.
